# チケットをまとめて実装する

範囲：`$ARGUMENTS`

1件ごとの手順は `/implement-ticket` のとおりです。このskillは、どのチケットをどの順で進めるかを決め、1件ずつ `/implement-ticket` を呼び出し、止まったときの扱いを決めます。人が席を外していても進められるように、聞くことは最初にまとめて聞きます。

## 必ず守ること

- **1件ずつ進める。** 並行して進めない。作業ツリーは1つしかない。
- **1件ごとに、`/implement-ticket` の手順を全部通す。** 実装とレビューを省かない。複数のチケットをまとめて実装させたり、まとめてレビューさせたりしない。
- **チケットごとに、実装とレビューのサブエージェントを新しく起動する。** 前のチケットのものを使い回さない。
- **1チケットが1コミット。** 複数のチケットを1つのコミットにまとめない。
- **ブランチを切らない。PRを作らない。プッシュしない。**
- **レビューが通らなかったチケットを、コミットして先へ進まない。**

## 1. 範囲と順番を決める

| 引数                | 範囲                                                      |
| ------------------- | --------------------------------------------------------- |
| なし                | `todo` が残っている、いちばん手前のマイルストーンのチケット |
| `M2`                | そのマイルストーンの `todo`                               |
| `T-001 T-002 T-004` | 挙げられたチケット                                        |
| `3件` のような件数  | 上の範囲のうち、先頭からその件数                          |
| `全部`              | `todo` のすべて                                           |

```bash
pnpm tickets --status todo                  # todo の一覧
pnpm tickets --status todo --milestone M0   # マイルストーンで絞る
pnpm tickets:next                           # いま着手できるもの
```

範囲のチケットを、`depends_on` をたどって、先に終わっている必要があるものが前に来るように並べる。同じ条件なら、IDの若い順にする。

範囲の外のチケットに依存していて、それが `done` でないチケットは、進められない。順番から外し、理由を控える。依存先を勝手に範囲へ足さない。

## 2. 始める前に確かめる

次のどれかに当たったら、始めずに報告する。

- いまいるブランチが `main` ではない。作業ツリーに、コミットしていない変更がある。
- 手元の `main` が `origin/main` と分かれている。
- `pnpm check` が落ちる。土台が壊れていると、どのチケットのレビューも通らない。

リモートがあれば、ここで1回だけ取り込む（`git fetch origin`、遅れているだけなら `git pull --ff-only`）。途中では取り込まない。

## 3. 最初にまとめて聞く

範囲のチケットを読み、次を1回でまとめて示して、答えをもらう。

1. **進める順番。** ID、題、大きさの一覧。外したチケットがあれば、その理由。
2. **「未決事項」があるチケット。** チケットごとに、決めることを示す。いま決めるか、そのチケットを飛ばすかを選んでもらう。
3. **設計書の「案」「未決」に当たったときの扱い。** 次のどちらかを選んでもらう。
   - 案のとおりに進める。進めたチケットで、採用したことを設計書に書き戻す
   - そのチケットを飛ばす

答えをもらったら、以後は聞かずに最後まで進める。引数でチケットのIDが挙げられていて、決めることが何もないときは、聞かずに始めてよい。

## 4. 1件ずつ進める

順番の先頭から、次を繰り返す。

1. `pnpm tickets:next` に、そのチケットが出ているかを見る。出ていなければ、飛ばして理由を控える。
2. Skillツールで `implement-ticket` を、チケットのIDを引数にして呼び出す。呼び出せないときは、`.claude/skills/implement-ticket/SKILL.md` を読み、その手順をそのまま実行する。
3. 結果を控える。コミットのIDとレビューの回数、または、飛ばした理由、止まった理由。
4. 次のチケットへ進む。

進み具合が見えるように、順番の一覧をタスクにして、終わるたびに更新する。

`/implement-ticket` の手順のうち、人に聞く、指示を待つ、とある箇所は、次のように読み替える。

| `/implement-ticket` で起きたこと                 | このskillでの扱い                                                                                         |
| ------------------------------------------------ | --------------------------------------------------------------------------------------------------------- |
| 「未決事項」がある                               | 3で決めてもらっていれば、その内容で進める。実装のサブエージェントに渡し、設計書かADRに書かせる。決まっていなければ飛ばす |
| 設計書の「案」「未決」に当たった                 | 3の答えに従う                                                                                             |
| `status` が `todo` でない、依存が終わっていない  | 飛ばす                                                                                                    |
| リモートの取り込み                               | しない。2で済ませている                                                                                   |
| 範囲の外で見つかったこと                         | その場では聞かず、控えておく。最後にまとめて聞く                                                          |
| 1件ごとの報告                                    | 1〜2行にとどめる。詳しくは最後にまとめる                                                                  |
| コミットせずに止まった                           | **全体を止める**（下の「5. 止める」）                                                                     |

飛ばしたチケットに依存するチケットは進められないので、あわせて飛ばす。

## 5. 止める

次のどれかで、全体を止めて報告に進む。

- 範囲のチケットが、すべて終わったか、飛ばされた。
- 件数の指定があり、その件数をコミットした。
- **コミットせずに止まったチケットが出た。** 実装のサブエージェントが止めた、レビューが3回で通らなかった、実装とレビューの意見が割れた、検査が落ちる、のどれか。変更が作業ツリーに残っているので、次のチケットには進めない。変更を捨てない。退避（`git stash`）もしない。
- `git` の状態が想定と違う。`main` にいない、覚えのない変更がある、など。

## 6. 報告する

- **結果の一覧。** チケットごとに、コミット済み（コミットのID）、飛ばした（理由）、止まった（理由）と、レビューの回数
- 止まったチケットがあれば、残っている指摘と、作業ツリーに何が残っているか
- 飛ばしたチケットを進めるために、人が決める必要があること
- 設計書の「案」を採用して、確定に書き換えた箇所
- 範囲の外で見つかったこと。チケットにするかどうかを聞く（する場合は `/create-ticket`）
- プッシュしていないこと。手元の `main` が `origin/main` より何コミット進んでいるか（`git status -sb`）
- 次に着手できるチケット（`pnpm tickets:next`）
