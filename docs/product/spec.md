# 仕様（v1）

Brainoid Notesは、チームのための小さなWikipediaです。人がScrapboxのように書き、AIが型を付け、エージェントがそれを読みます。中身はすべてMarkdownで持ち出せます。

この文書は、2026-11-13時点の仕様書とUIプロトタイプをリポジトリ用にまとめ直したものです。以後は、このリポジトリの文書を正とします。

- 元の仕様書：https://claude.ai/artifact/Bdzm3bT3ismx5aCBmbnrKc
- UIプロトタイプ：https://claude.ai/artifact/7Hr4U6GEUPyo844wRyERU3

どちらも、作成者が共有するまでほかの人は開けません。

## 誰の、どんな問題を解くか

- **最初の利用者**：自分たちの研究チーム。分野はシステム生物学で、ときどきKaggleにも取り組む。大学と企業のメンバーがいる。
- **問題**：論文（外の知識）と、実験や考え（内の知識）が同じ場所になく、エージェントが両方を突き合わせられない。
- **約束すること**：ページに型とプロパティがあるので、エージェントが漏れなく列挙でき、決まった欄に書き戻せる。

既存ツールとの違いは「軽さ」「Markdownで持ち出せること」「AIが構造を保守すること」に置きます。型を付けられること自体は、TanaやCapacitiesにもあります。

## v1の目標

v1の目標は、自分たちのチームが今のツールの代わりに毎日使うことです。

- チームが1週間、Obsidianを開かずに研究の記録を続けられる。
- エージェントに「この論文の主張に反する実験はあるか」と聞くと、型をたどった答えが返る。
- Markdownを読み込んで書き出すと、元と同じになる。
- 全ページをいつでもMarkdownで持ち出せる。

## 対象外

| 作らないもの                                   | 理由                                                           |
| ---------------------------------------------- | -------------------------------------------------------------- |
| テーブル表示、クエリUI                         | 人は絞り込まず、問い合わせはエージェントに任せる               |
| フォルダ、ディレクトリ                         | 木があると分類が始まり、リンクとクラスによる整理が崩れる       |
| プラグイン                                     | 拡張はオントロジーのテンプレートで行う                         |
| ページ単位の権限、ワークスペースをまたぐリンク | 権限はワークスペース単位に絞る                                 |
| エージェントによる本文の書き換え               | 同時に編集している人の入力を潰す。v1は提案、新規作成、追記まで |
| アプリ内のAI                                   | 外部のエージェントが同じ口から提案を書けるので、後回しにできる |
| グラフ表示、モバイルアプリ                     | v1では優先しない                                               |
| 課金の仕組み                                   | v1の利用者は自分たちだけ                                       |

## 設計原則

迷ったときは、次の7つに照らして決めます。

1. **書くのは人間、型付けはAI、承認するのは人間。** 人が承認したものだけを事実として扱う。
2. **正本は共有ドキュメント。** Markdownは正本ではなく、いつでも損失なく書き出せる形式として保証する。
3. **グラフは1つ。** クラスもプロパティもページで、関係はラベル付きのリンクとして同じグラフに載る。
4. **スキーマは提案であって強制ではない。** 型に合わない値も、定義のないプロパティも保存できる。
5. **フォルダは作らない。** 「何についてか」はクラスで、「誰が読むか」はワークスペースで分ける。
6. **書き込みの経路は1つ、読み取りは索引から。** 人もエージェントも同じ経路で書き、一覧や検索は索引を読む。
7. **製品からはAIにデータを送らない。** 送られるのは、利用者が自分のエージェントをつないだときだけ。

## 未決事項

| 項目                                 | 決めること                                              |
| ------------------------------------ | ------------------------------------------------------- |
| クラスのページの識別                 | `type` で明示するか、`subclass_of` や参照から推定するか |
| `range` と `same_as` の書き出し      | RDFにするときの述語                                     |
| `モデル` の外部語彙                  | 対応させる型があるか                                    |
| 認証の方式                           | メールのリンク、OAuthなど                               |
| 提案を出すタイミング                 | 編集が止まってから何秒待つか（アプリ内のAIを足すとき）  |
| エージェントの回数上限               | 具体的な値                                              |
| デプロイ先                           | どこで動かすか                                          |
| 価格、利用規約、プライバシーポリシー | チームの外に公開する前に決める                          |

## リスク

| リスク                                     | 対策                                                                   |
| ------------------------------------------ | ---------------------------------------------------------------------- |
| 人が提案を承認し続けず、構造が欠ける       | ルールでの型付けを先に行い、抜けをクラスページに表示する               |
| Markdownとの往復で内容が欠ける             | ノードを絞り、往復テストを最初から回す                                 |
| 共同編集エディタの作り込みに時間を取られる | 薄く一通り通してから深める                                             |
| 研究室ではCosenseが無料で使える            | 価格ではなく「型付きでエージェントから引ける」ことで選ばれる必要がある |
