## 目的

エラーの形、入力の検証、ログを最初にそろえる。以降のルートが同じ形で書けるようにする。

## 参照

- [APIと権限](../design/api.md)
- [コードとテストの書き方](../dev/conventions.md)

## やること

- エラーの共通の形 `{ error: { code, message } }` と、エラー用のミドルウェア
- zodで入力を検証する部品
- リクエストごとのIDとログ（本文やトークンを出さない）
- テスト用の薄いヘルパー
- 404と、想定外のエラーの扱い

## やらないこと

- 認証（T-021）

## 受け入れ条件

- [ ] 検証に失敗したリクエストが、400と共通の形のエラーを返す
- [ ] 想定外の例外が500と共通の形を返し、スタックを外に出さない
- [ ] ルートの書き方の例が1つあり、テストが付いている
