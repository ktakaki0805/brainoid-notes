# ADR-0011: デザインシステムはAstryxを使う

- 状態：採用
- 日付：2026-11-13

## 状況

UIプロトタイプで、画面の構成と動きは決まった。部品（ボタン、メニュー、検索バー、候補の一覧など）を自分たちで作ると、キーボード操作、アクセシビリティ、テーマの作り込みに時間を取られる。v1で時間をかけたいのは、エディタと型付けである。

## 決定

画面の部品、トークン、テーマに [Astryx](https://github.com/meta/astryx)（`@astryxdesign/core`）を使う。

- 見た目は、Astryxの neutral テーマを土台にした Brainoid のテーマにする。変えるのは、アクセント色と書体だけ。
- 色や余白の独自の変数は持たない。足りない色は、テーマに足す。
- 画面の構成と動きの基準は、UIプロトタイプのままにする。見た目がプロトタイプと食い違ったら、Astryxに合わせる。

## 理由

- 部品が多く、キーボード操作とアクセシビリティが部品に入っている
- 検索のオーバーレイ（`CommandPalette`）、候補の一覧（`Typeahead`）、サイドバー（`SideNav`）、プロパティの一覧（`MetadataList`）など、この製品に要る部品がそろっている
- CLIが部品の仕様を返すので、Claude Codeが推測せずに正しいpropsで書ける
- ビルド済みのCSSとJSで動き、ビルドの設定を足さずに済む
- テーマはCSSの変数の上書きなので、部品を包んだり写したりせずに見た目を変えられる

## 影響

- **ベータ版である。** 0.x で、ほぼ毎日リリースがある。版は完全に固定し、`@astryxdesign/*` は必ず同じ版にそろえて上げる（手順は `docs/dev/setup.md`）
- **新しいWebの機能に依存する。** Popover API、CSS anchor positioning、`light-dark()` を使う。対応ブラウザは [ADR-0012](0012-modern-web-guidance-and-baseline.md) で決める
- **書き方の決まりが増える。** 色や余白を直書きしない、`<div>` で組まない、部品のpropsを先に読む。決まりは `apps/web/CLAUDE.md` にある
- **テーマの生成物をコミットする。** テーマを変えたら `pnpm theme:build` で作り直す。ずれは `pnpm check` で見つかる
- **書体はGoogle Fontsから読み込んでいる。** 自分たちで配るかどうかは未決（T-075までに決める）
- **ダークモードはv1では出さない。** テーマにはダークの値も入っているので、出すと決めたら `Theme` の `mode` を変える

## 見送ったこと、未決のこと

- **部品を自分たちで作る**：見送り。上の「状況」のとおり
- **StyleXのコンパイラを入れる**：いまは入れない。部品のpropsとトークンで足りなくなったら、`@astryxdesign/build` を入れるADRを書く
- **AstryxのMCPサーバー**：入れない。CLIで同じ文書を手元で引ける
- **`@astryxdesign/richtext`（Lexicalで作られたエディタの部品）を土台にするか**：未決。Lexicalの版をこの部品に合わせる必要があり、独自のノードと共同編集を載せられるかも確かめる必要がある。T-015で決める
