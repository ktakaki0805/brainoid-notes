# ADR-0010: チケットはリポジトリの中のMarkdownで管理する

- 状態：採用
- 日付：2026-11-13

## 状況

複数人が、主にClaude Codeで開発する。小さなチケットに分け、チケットに沿って実装したい。

## 決定

チケットは `docs/tickets/` に1チケット1ファイルで置く。状態はファイルの先頭に書く。ブランチとPRは使わず、1チケットを1コミットで `main` に入れる。

## 理由

- Claude Codeがそのまま読める
- チケットと実装が同じコミットで更新される
- ファイルが分かれているので、状態の更新で衝突しない

## 影響

- `main` の上では、チケットは `todo` か `done` のどちらか
- 着手中かどうかは、リポジトリからは分からない。着手するときはチームに知らせる
- レビューは、コミットの前に、実装とは別のサブエージェントが行う（`docs/dev/workflow.md`）
- 一覧と整合性の確認は `scripts/tickets.mjs` で行う
