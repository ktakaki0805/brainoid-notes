# Markdownの形式

1ページが1ファイルです。プロパティはfrontmatter、本文はMarkdownになります。読み込んで書き出すと元と同じになることを、往復テストで保証します。

変換の実装は `@brainoid/editor`（本文）と `@brainoid/core`（frontmatter）に置きます。骨組みは `packages/editor/src/`、リンクとfrontmatterはT-011です。

## 例

```markdown
---
type: "[[実験]]"
実施日: 2026-11-10
担当: ["[[田中]]"]
使用モデル: "[[EGF経路モデル v2]]"
検証対象: "[[EGF刺激でERKは一過的に活性化する]]"
結果: 支持
---

# 実験12

[[EGF経路モデル v2]]でパラメータを推定し直した。
```

```markdown
---
type: "[[プロパティ]]"
value_type: link
range: "[[主張]]"
---

# 検証対象

実験が確かめようとしている主張。
```

## ファイル

- ファイル名はタイトルに `.md` を付けたもの。ファイル名に使えない文字は置き換える（規則はT-035で決める）。
- 本文の先頭は `# タイトル`。タイトルの正はこの見出しで、ファイル名は補助。
- フォルダは作らない。全ページを1つのフォルダに並べる。

## frontmatter

- 形式はYAML。型もプロパティもないページには、frontmatterを付けない。
- キーの順番は、`type`、`subclass_of`、`properties`、`value_type`、`range`、`choices`、`aliases`、`same_as`、そのあとに利用者のプロパティを保存されている順に並べる。
- 値の書き方は次のとおり。

| 値       | 書き方                                   | 例                        |
| -------- | ---------------------------------------- | ------------------------- |
| リンク   | 引用符つきの `[[タイトル]]`              | `"[[田中]]"`              |
| 文字列   | そのまま。YAMLとして曖昧なら引用符で囲む | `支持`                    |
| 数値     | そのまま                                 | `2023`                    |
| 日付     | `YYYY-MM-DD`                             | `2026-11-10`              |
| 複数の値 | 1行のリスト                              | `["[[ERK]]", "[[EGFR]]"]` |

- 複数の値を持てるプロパティは、値が1つでもリストで書く。
- 値のないプロパティは書かない。
- 承認前の提案は書かない。

## 本文

エディタで使えるのは、Markdownで表現できるものだけです。使える記法は `packages/editor/src/transformers.ts` の一覧が正です。

| 要素               | 記法                                 |
| ------------------ | ------------------------------------ |
| 段落               | 空行で区切る                         |
| 見出し             | `#` から `###`                       |
| 箇条書き、番号付き | `-`、`1.`                            |
| 引用               | `>`                                  |
| 太字、斜体         | `**太字**`、`*斜体*`                 |
| 外部へのリンク     | `[表示](https://...)`                |
| ページへのリンク   | `[[タイトル]]`、`[[タイトル\|表示]]` |

ページへのリンクは、書き出すときにページIDからタイトルを引いて書きます。読み込むときは、タイトルからページIDを引きます。

## 読み込み

- リンク先のタイトルが同じ取り込みの中にあれば、そのページにつなぐ。なければ「まだないページ」へのリンクにする。
- 知らないfrontmatterのキーは、利用者のプロパティとして取り込む。定義のないプロパティとして扱えるので、捨てない。
- 使えない記法（表、画像など）の扱いはT-060で決める。黙って捨てず、取り込みの結果に一覧を出す。

## 保証すること

1. **書き出しの往復**：ページを書き出して読み込むと、本文もプロパティも元と同じになる。
2. **読み込みの往復**：この文書の規則どおりに書かれたMarkdownは、読み込んで書き出すと1文字も変わらない。
3. **規則どおりでないMarkdown**（キーの順番が違う、引用符の付け方が違うなど）は、1回目の書き出しで規則どおりに直る。2回目以降は変わらない。

往復テストは `packages/editor/src/markdown.test.ts` にあります。ノードや変換規則を足すときは、同じコミットでここに例を足します。
