# 共同編集と保存

同期サーバー（Hocuspocus）が、共同編集の中継、Yjsの保存、索引の更新、編集者の記録を受け持ちます。ひな型にあるのは文書名の確認だけで、残りはチケットで足します。

## 選んだもの

- **同期サーバーはHocuspocus v4を自分たちで動かす。** 認証と保存のフックがあり、サーバー側から文書に直接つなげる。Node.js 22以降が必要。（[ADR-0003](../adr/0003-hocuspocus.md)）
- **Yjsのバインディングは `@lexical/yjs`（Yjs 13向け）。** Yjs 14向けの `@lexical/y` は実験的。2つは保存形式が異なり、1つの文書はどちらか一方しか使えないので、実データを貯める前に決めた。（[ADR-0002](../adr/0002-lexical-and-yjs-binding.md)）

## 文書名

1ページが1つのYjsドキュメントで、文書名は `<workspaceId>/<pageId>` です。組み立てと解析は `apps/sync/src/document-name.ts` を使います。形式に合わない名前での接続は断ります。

## 接続の流れ

| 段階     | フック            | すること                                                                       | チケット     |
| -------- | ----------------- | ------------------------------------------------------------------------------ | ------------ |
| 接続     | `onAuthenticate`  | セッションかトークンを確かめ、`can()` で権限を見る。閲覧者は読み取り専用にする | T-025        |
| 読み込み | `onLoadDocument`  | `page_docs` からYjsの状態を読む。なければ空の文書                              | T-025        |
| 変更     | `onChange`        | 誰の変更かを `edit_log` に記録する                                             | T-038        |
| 保存     | `onStoreDocument` | Yjsの状態を保存し、索引を書き直す                                              | T-025、T-026 |

Hocuspocus v4では、`onStoreDocument` に渡るのは `lastContext` と `lastTransactionOrigin` です。保存は接続以外（サーバー側の書き込み）からも起きるので、接続に固有の値は渡りません。

## 保存と索引の更新

保存のたびに、次の順で索引を書き直します（T-026）。

1. headlessのLexicalで本文を読み、Markdownと検索用の本文を作る。
2. `props` からプロパティを取り出す。`type` などの予約語も同じ扱い。
3. 本文のリンクを取り出す。
4. `page_index`、`page_props`、`page_links` を1つのトランザクションで置き換える。

索引はYjsの状態から作り直せるものです。索引を直接書き換えるコードは書きません。

## サーバー側からの書き込み

エージェントの書き込み、提案、承認は、APIサーバーが同期サーバーのサーバー側接続（`openDirectConnection`）を使って行います。開いている人の画面にすぐ反映されます。

- **プロパティと提案**：`props` と `proposals` のマップを直接書く。
- **本文への追記**：headlessのLexicalをその文書につないで書く。`root` のYjsを直接書かない。

APIサーバーと同期サーバーを別プロセスにする場合のつなぎ方（同期サーバーに内部用のHTTPの口を作る、など）は、T-040とT-047で決めます。ひな型では2つのアプリに分けてありますが、1プロセスにまとめる選択肢も残っています。

## タイトル

タイトルはYjsに入れません。作成と改名はAPIを通し、`pages` の一意制約で守ります（T-024）。リンクはページIDを持つので、改名してもリンクは切れません。改名を開いている人に伝える方法は、T-027で決めます。

## 権限の失効

メンバーを外したら、その人の開いている接続を切ります（T-067）。共同編集は接続時にしか権限を確かめないので、切らないと編集を続けられてしまいます。トークンの失効と、エージェント接続のスイッチも同じです。

## 規模

最初は同期サーバー1台で動かします。複数台にするときはRedisが要りますが、必要になるまで入れません。
