# 権限、トークン、AIへのデータの渡し方

製品からはAIにデータを送りません。送られるのは、利用者が自分のエージェントをつないだときだけです。どのAIに何を渡すかは、ワークスペースの所有者が決めます。

## 人の権限

- 権限はワークスペース単位だけ。役割は所有者、編集者、閲覧者の3つ（表は [api.md](api.md)）。
- ワークスペースを分ける基準は「見せてはいけない相手がいるか」だけ。整理のために分けない。
- リンクも一覧もワークスペースの中で閉じる。またぐ仕組みは作らない。
- メンバーを外したら、その人の開いている接続を切る。

## エージェントのトークン

- 発行できるのは所有者だけ。権限は読み取り、提案、直接書き込みの3段階で、既定は提案。
- 発行時に1回だけ表示する。DBにはハッシュだけを保存する。
- いつでも失効できる。失効したら、そのトークンの接続を切る。
- 所有者は、ワークスペースごとにエージェント接続を丸ごと止められる。機密性の高いワークスペースのためのスイッチ。

## AIとデータ

- アプリ内のAIはv1では作らない。サーバーからAIのAPIを呼ぶコードを入れない。
- あとで足す場合は、既定でオフ、ワークスペースごとに有効化、AIのAPIキーは利用者が自分のものを入れる。
- エージェントの書いた提案は、人が承認するまで事実として扱わない。

## 記録

| 記録           | 内容                                           | チケット |
| -------------- | ---------------------------------------------- | -------- |
| 編集の記録     | すべての編集について、人かエージェントか、誰か | T-038    |
| 提案の記録     | 提案者、承認者または却下した人、時刻           | T-040    |
| アクセスの記録 | どのトークンが、いつ、どのページを読んだか     | T-072    |

Yjsは誰が書いたかを人の単位で持たないので、記録はサーバー側で付けます。

## 書き出しと削除

- 全データをMarkdownで持ち出せる。
- ページを消したら、Yjsの状態も索引も消す（消し方の詳細はT-024で決める）。

## 制約

索引、検索、MCPのためにサーバーは平文を読む必要があります。運営者にも読めない形の暗号化（エンドツーエンド）はできません。それでは足りない組織向けには、自前のサーバーで動かす版が将来の選択肢になります。

## 実装で気をつけること

- 秘密の値（DBのURL、セッションの鍵）は環境変数で渡す。`.env` はコミットしない。
- 入力はすべてzodで検証する。SQLはDrizzleを通す。文字列を連結してSQLを作らない。
- 同期サーバーは、認証を入れるまで本番で起動できないようにしてある（`apps/sync/src/server.ts`）。
- ログにトークン、Cookie、本文を出さない。

## チームの外に公開する前に

- 利用規約とプライバシーポリシーを用意し、専門家に確認する。
- 大学と企業のデータを預かるので、データの置き場所と、エージェント経由でAIに渡る範囲を説明できるようにする。
